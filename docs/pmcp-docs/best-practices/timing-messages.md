# Timing Messages

Source: https://my.pathmate.app/pmcp-documentation/doc-6-0/best-practices/timing-messages · fetched 2026-09-29 · condensed extract (quotes verbatim)

Four approaches to timing coach messages and reminders.

| Approach | Pros | Cons | Use when | Don't use when |
|---|---|---|---|---|
| **Fixed time** (set by designers) | Simple; consistent; **predictable**: "you know when the users are contacted by the coach, making the design of further coaching dialogues easier, as you can avoid message interferences"; users know when to expect contact | Not personalised; inflexible | The user can reply later ("the 'perfect' timing … is not crucial"); daily routine; study comparability. Example: daily morning health-literacy lessons | Immediate reaction needed; burdensome response (e.g. needs a measurement device) |
| **User-defined time** | User control, engagement | User burden; users may lack insight; **"Coach designers cannot predict when users will be contacted, possibly leading to message interference."** | High personalisation; concrete actions ("When is the best time for you to measure your blood pressure in the morning?"). Example: medication reminder | "Less is more": don't make users define many contact times |
| **Smart timing** (algorithms/data) | Highly personalised; dynamic | Complex; privacy; unpredictable | Enough data; timely response required | Privacy-sensitive users; limited resources |
| **Event-based** (user actions) | Relevant; engaging | Depends on user actions; possible overload | User actions naturally trigger a response | Actions too frequent |

Tip (smart timing): a simple rule of thumb is to contact users at the time they were active the day before.

## Coach-led vs. user-driven

- **User-driven:** the user starts and guides dialogues. Not intrusive, but the coach stays inactive if the user doesn't engage.
- **Coach-led:** the coach contacts the user proactively. Gives a "nudge" and a stronger narrative, but risks being bothersome.
- **Mixed models** are possible and often beneficial.

**Relevance to pile-up (ours):** the page names "message interference" as a risk of user-defined times, but gives no mechanism for handling it. ALEX uses user-defined times for spirometry, medication and bedtime.

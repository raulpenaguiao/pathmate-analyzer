## Why it took 4 attempts: two real reliability bugs found in shared tooling

Both bugs are the same root cause as the long-documented "element is not
enabled" Vaadin quirk (this project has hit it repeatedly, in the browser
UI itself, not just this tool) — but here it persisted for the *entire*
default 30s Playwright actionability wait, not the usual millisecond-scale
flakiness, and neither call site had any retry around the click itself.

- **Run 1**: no output file written; hard-stopped in phase 3 with "Rules
  tab not on screen" — a known, already-documented drift where the Rules
  view can lose focus between runs. Fixed by re-confirming the tab live
  before retrying (not a code change).
- **Run 2**: crashed with an unhandled `TimeoutError` in
  `_rules_nav.py::close_windows()` at `await btn.last.click()` (the "Close"
  button on the rule-editor modal). No retry wrapper existed around this
  click. **Fix**: wrapped the click in a 4-attempt retry loop
  (`timeout=8000` per attempt, 1s wait between attempts) inside the existing
  outer per-modal loop.
- **Run 3**: got past `close_windows()` (confirming that fix), then hit the
  identical class of error at a *different* unguarded click:
  `_rules_nav.py::open_rule_modal()` at `await btn.click()` (the sender's
  toolbar Edit button). Its outer loop (`range(2)`) had no try/except around
  either `select_node()` or the click, so the exception still propagated
  past the loop. **Fix**: wrapped both `select_node()` and `btn.click()` in
  try/except-and-continue, and widened the loop to `range(4)`.
- **Run 4**: succeeded end to end with both fixes in place.

Both fixes are in `tools/coaching-bundle-export/_rules_nav.py`
(`close_windows()` and `open_rule_modal()`), syntax-verified via
`ast.parse` before each retry. No other unguarded click sites were hit in
this run, but this doesn't rule out others existing elsewhere in the export
tool (`_menu_nav.py`, `export_coaching.py`) — only what actually executed
this session was exercised.
